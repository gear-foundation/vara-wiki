# wVARA Overview

Vara.eth programs pay for execution in wVARA. The Ethereum Router’s `wrappedVara()` getter identifies the ERC-20 for its deployment.

## What is wVARA?

On Ethereum mainnet, holders can use wVARA to fund a program’s Executable Balance. The current proof-of-authority middleware uses a configured validator set. Public staking and on-chain validator payouts are unavailable in this deployment. See [Validators & Staking](/docs/vara-eth/economics/validators-staking).

## wVARA vs ETH

Both tokens play a role in Vara.eth, but for different purposes:

| | ETH | wVARA |
|---|---|---|
| **Who pays** | Users | Programs |
| **What it covers** | L1 transaction gas | Off-chain execution cost |
| **When it's used** | Every message send | Every message processed |
| **Where it lives** | User's wallet | Program's Executable Balance |

When a user sends a message to a Vara.eth program:
- The **user** pays ETH for the Ethereum transaction (L1 gas)
- The **program** pays wVARA for executing the message (computation cost)

This separation is the **Reverse Gas Model** — users don't need wVARA to interact with programs.

## Token Mechanics

### ERC-20 on Ethereum

wVARA is a standard ERC-20 token deployed on Ethereum. Holders can transfer it to another Ethereum address.

See [Contract Addresses](/docs/vara-eth/reference/contract-addresses) for the wVARA token configured by the Router on each network.

### Vara.eth wVARA vs. Bridge WVARA

The [Vara Network BEEFY bridge](/docs/vara-network/bridge/developer_hub#token-contracts) mints and burns its own WVARA. It shares the ticker but not the contract address. Use the Router's token for executable balance; equal tickers do not make the tokens interchangeable.

### Decimals

The Ethereum Mainnet Router's wVARA uses **12 decimals**. Read `decimals()` from the Router's token when converting amounts for another deployment.

```
1 wVARA = 1_000_000_000_000 (1e12) base units
```

## Where wVARA Flows

A holder approves the program’s Mirror to spend the intended amount, then calls `executableBalanceTopUp(value)`. The Mirror transfers the approved tokens to the Router and emits a top-up request. The runtime credits the program’s Executable Balance when it processes that request.

## Balance Types

Each program has **two key balances** you should monitor:

### Executable Balance (wVARA)

The runtime tracks this balance for each program and charges it for message execution. An underfunded message can fail.

- Funded via `executableBalanceTopUp(value)` on the Mirror (with prior ERC-20 approve)
- Charged according to the gas burned during execution
- Cannot be withdrawn by the program
- Can be funded by anyone (developer, users, sponsors)
- Transferred to inheritor on program exit

See [Funding Executable Balance](/docs/vara-eth/interact/funding-executable-balance) for management details.

### Program Value Balance (Owned Balance, Ether)

Programs can also hold **native Ether** in addition to wVARA. This is useful for programs that need to interact with ETH-based contracts or hold ETH as part of their logic.

- Funded via `sendMessage{ value: ethAmount }` (payable)
- Or via direct Ether transfer to the Mirror contract
- Controlled by program logic
- Transferred to inheritor on program exit

In `@vara-eth/api` state reads, these appear as:
- `state.executableBalance` — execution budget (wVARA base units)
- `state.balance` — program value balance
