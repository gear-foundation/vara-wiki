# Funding Executable Balance

Every Vara.eth program needs wVARA in its **Executable Balance** to pay for computation. This is the core of the [reverse gas model](/docs/vara-eth/economics/reverse-gas-model) — users pay ETH for L1 transactions, but the program itself pays wVARA for execution.

## How to Fund

### Mirror Contract (Primary Method)

The `executableBalanceTopUp` function on the Mirror contract is the primary way to fund a program. Anyone can call it.

Use the token from your Router's `wrappedVara()` getter, not the Vara Network bridge's WVARA. Read that token's `decimals()` to convert the amount; the Ethereum Mainnet Router's wVARA has 12 decimals.

This example targets Ethereum Mainnet. Set `routerAddress` from the [Vara.eth deployment table](/docs/vara-eth/reference/contract-addresses#ethereum-mainnet), `mirrorAddress` to the program you intend to fund, and `signer` to your connected wallet. For another deployment, change the chain ID and Router together.

```typescript
import { Contract, parseUnits, ZeroHash } from 'ethers';

const network = await signer.provider?.getNetwork();
if (network?.chainId !== 1n) throw new Error('Connect to Ethereum Mainnet');

const router = new Contract(routerAddress, [
  'function programCodeId(address program) view returns (bytes32)',
  'function wrappedVara() view returns (address)',
], signer);
if (await router.programCodeId(mirrorAddress) === ZeroHash) {
  throw new Error('Mirror is not registered with this Router');
}

const wvara = new Contract(await router.wrappedVara(), [
  'function decimals() view returns (uint8)',
  'function approve(address spender, uint256 amount) returns (bool)',
], signer);
const amount = parseUnits('100', await wvara.decimals());
await (await wvara.approve(mirrorAddress, amount)).wait();

const mirror = new Contract(mirrorAddress, [
  'function executableBalanceTopUp(uint128 value)',
], signer);
await (await mirror.executableBalanceTopUp(amount)).wait();
```

<Callout type="note" title="Approval Required">
  You must first approve the program address (Mirror) as spender for your wVARA tokens.
</Callout>

### CLI

```bash
ethexe tx executable-balance-top-up "$PROGRAM_ID" "$AMOUNT_BASE_UNITS" \
  --approve \
  --ethereum-rpc "$RPC" \
  --ethereum-router "$ROUTER" \
  --sender "$SENDER"
```

**Parameters:**

- `$PROGRAM_ID` — Mirror contract address
- `$AMOUNT_BASE_UNITS` — Amount in the Router token's base units (`10000000000000` for 10 wVARA on Ethereum Mainnet)
- `--approve` — Check that the selected Router recognizes the Mirror, then approve wVARA spending before the top-up. Verify that `$RPC` and `$ROUTER` point to the intended deployment before running the command.

### Etherscan

1. Open the [Router for your network](/docs/vara-eth/reference/contract-addresses) in its block explorer and connect your wallet to that same network. In "Read as Proxy" (or "Read Contract"), call `programCodeId` with the Mirror address. Do not approve if the result is zero.
2. Read `wrappedVara()` on that Router. On the returned token contract, call `approve` with the verified Mirror as `spender` and the exact amount in base units.
3. On that Mirror, open "Write as Proxy" (or "Write Contract") and call `executableBalanceTopUp` with the same amount.

## How Execution Is Charged

The runtime converts the gas burned during ordinary execution to wVARA base units and deducts that amount from the program’s Executable Balance. The sender pays the Ethereum transaction fee in ETH. For the billing rule and its exception, see [Reverse Gas Model](/docs/vara-eth/economics/reverse-gas-model#execution-pricing).

## Funding Models

Different funding strategies suit different applications:

**Developer-Funded (Patron Model)** — Developer pre-funds the program. Best for onboarding, demos, consumer-facing apps, and games where you want zero-friction UX.

**Revenue-Funded** — Program logic collects fees (e.g., swap fees in a DEX) and the developer periodically tops up from revenue. Best for DeFi protocols and fee-generating services.

**User-Funded** — Users contribute to the Executable Balance directly. Best for per-action pricing, premium features, or pay-per-use services.

**Sponsor-Funded** — DAOs, grants, or ecosystem partners fund programs. Best for public goods, community tools, and infrastructure.

## What Happens When Balance Runs Out

When the Mirror accepts a message on Ethereum, it emits `MessageQueueingRequested` and the sender pays L1 gas. Execution on Vara.eth can still run out of gas, consume part of the program’s balance, and return an error. [Mirror event](https://github.com/gear-tech/gear/blob/v1.10.0/ethexe/contracts/src/Mirror.sol#L215-L230) · [Insufficient-balance example](https://github.com/gear-tech/gear/blob/v1.10.0/ethexe/processor/src/tests.rs#L1442-L1494)

A top-up funds subsequent execution. Check the reply and the program state for the original message ID before deciding whether to retry. Resubmitting a message whose outcome is unknown can repeat the application action.

## Monitoring Balance

### TypeScript SDK

```typescript
// Read state by current state hash, then use executableBalance field
const mirror = getMirrorClient(programId, signer, publicClient);
const stateHash = await mirror.stateHash();
const state = await api.query.program.readState(stateHash);
console.log(`Executable balance: ${state.executableBalance} base units`);
```

### CLI

```bash
ethexe tx query "$PROGRAM_ID" \
  --ethereum-rpc "$RPC" \
  --ethereum-router "$ROUTER" \
  --sender "$SENDER"
```

In `v1.10.0`, this command shows mirror metadata and ETH balance.
For executable (wVARA) balance monitoring in SDK, read state through `api.query.program.readState(...)` and use `state.executableBalance`.

Set up automated alerts when balance drops below a threshold to avoid service interruption.

### What Types of Balances Does a Program Have?

| Balance                | Purpose                                    | Who Controls                            |
| ---------------------- | ------------------------------------------ | --------------------------------------- |
| **Executable Balance** | Pays for program execution (compute costs) | Router (consumed automatically)         |
| **Program Value Balance (Owned Balance)** | Value held by program logic (payable flow) | Program logic (via Mirror payable flow) |
