title: Ethereum → Vara App Guide

This guide follows a one-way application ping from Ethereum to Vara. The Vara light client authenticates Ethereum finality; the receipt proof authenticates the execution log. Your receiving program decides which emitter, event, and payload it accepts. The [Vara → Ethereum App Guide](/docs/vara-network/bridge/developer-guide-vara-eth) uses a separate example; it is not a reply path for this ping.

## High-Level Architecture

1. An Ethereum application contract emits the ping event in a successful transaction.
2. A relayer builds a proof of the receipt against finalized Ethereum history supported by the checkpoint light client on Vara.
3. The Historical Proxy routes the proof to the verifier configured for the Ethereum slot. After verification, it forwards the authenticated receipt to the Vara application.

The example uses a Historical Proxy endpoint that forwards the **raw EIP-2718 receipt trie value**: an RLP list for a legacy receipt, or the type byte followed by the RLP payload for a typed receipt. Use a matching verifier and proof tool on your test deployment. The retained mainnet token path RLP-wraps typed receipts and is not the profile used by this example. Do not use a decoder fallback to accept both formats.

## Emit and Identify the Ping on Ethereum

This example emits `MessageRequested`, an application event, not a bridge-wide event ABI. Deploy it with the authorized Ethereum sender and the full 32-byte ID of your Vara program. Configure the Vara receiver to expect this emitter address, sender, and event ABI.

The constructors need both addresses. Before deploying `EthereumPingSender`, calculate the Vara actor ID with `generateProgramId(wasm, salt)` from `@gear-js/api`, using the receiver Wasm you will deploy and a fresh salt. Then deploy the receiver with that same Wasm and salt and pass the Ethereum contract address as its `emitter`. Confirm the receiver's initialization succeeded with the intended configuration before sending the ping.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.28;

contract EthereumPingSender {
    address public immutable sender;
    bytes32 public immutable destination;

    event MessageRequested(
        bytes32 indexed applicationId,
        address indexed sender,
        bytes32 indexed destination,
        bytes payload
    );

    constructor(address authorizedSender, bytes32 varaDestination) {
        require(authorizedSender != address(0) && varaDestination != bytes32(0), "invalid configuration");
        sender = authorizedSender;
        destination = varaDestination;
    }

    function sendMessage(bytes32 applicationId, bytes calldata payload) external {
        require(msg.sender == sender, "wrong sender");
        require(applicationId != bytes32(0) && payload.length <= 1024, "invalid ping");
        emit MessageRequested(applicationId, msg.sender, destination, payload);
    }
}
```

The 1,024-byte limit belongs to the ping application, not the receipt bridge. Use a unique application ID, and record the Ethereum chain, emitter address, transaction hash, and expected event. A transaction hash identifies the receipt, not an individual log.

## Relay the Original Receipt

1. Wait for Ethereum finality and for the matching checkpoint evidence to be accepted on Vara. An Ethereum transaction being mined does not meet either condition.
2. Build the execution receipt trie proof and the Beacon proof that binds it to authenticated Ethereum history. Send it to the configured Historical Proxy using the verifier and consumer interface for that slot.
3. Track the original Vara transaction and the receiver's finalized reply. If the result is unknown, reconcile the original submission rather than resending the source ping.

## Authenticate the Ping on Vara

Call `HistoricalProxy.Redirect` with the receiver's actor ID as `client` and the SCALE-encoded pair of strings `("Ping", "SubmitReceipt")` as `client_route`. The proxy prefixes that route to the verified arguments in this order: `(slot: u64, transaction_index: u64, receipt_rlp: Vec<u8>)`. The program returns `Result<H256, ReceiptError>` after its route prefix. Decode that result from the proxy's consumer reply; a successful redirect alone does not prove the ping was accepted.

The example uses Sails' string-prefixed SCALE routes. Create a Rust library crate with the following `Cargo.toml` and `src/lib.rs`. In `build.rs`, use `fn main() { sails_rs::build_wasm(); }`. Install the `wasm32v1-none` target for `nightly-2026-02-10`, then run `cargo +nightly-2026-02-10 build --release` and use the generated `.opt.wasm` for deployment.

```rust
#![no_std]

use alloy_consensus::ReceiptEnvelope;
use alloy_eips::eip2718::Decodable2718;
use alloy_sol_types::{sol, SolEvent};
use core::cell::RefCell;
use sails_rs::{
    collections::{BTreeMap, BTreeSet},
    prelude::*,
};

sol! {
    event MessageRequested(
        bytes32 indexed applicationId,
        address indexed sender,
        bytes32 indexed destination,
        bytes payload
    );
}

#[derive(Encode, Decode, TypeInfo)]
#[codec(crate = sails_rs::scale_codec)]
#[scale_info(crate = sails_rs::scale_info)]
pub enum ReceiptError {
    WrongProxy,
    InvalidReceipt,
    InvalidPing,
    AlreadyAccepted,
}

struct State {
    proxy: ActorId,
    emitter: H160,
    sender: H160,
    positions: BTreeSet<(u64, u64)>,
    pings: BTreeMap<H256, Vec<u8>>,
}

pub struct Ping<'a>(&'a RefCell<State>);

#[service]
impl<'a> Ping<'a> {
    #[export]
    pub fn submit_receipt(
        &mut self,
        slot: u64,
        transaction_index: u64,
        receipt_rlp: Vec<u8>,
    ) -> Result<H256, ReceiptError> {
        assert_eq!(Syscall::message_value(), 0, "do not attach value");
        let mut state = self.0.borrow_mut();
        if Syscall::message_source() != state.proxy {
            return Err(ReceiptError::WrongProxy);
        }
        let position = (slot, transaction_index);
        if state.positions.contains(&position) {
            return Err(ReceiptError::AlreadyAccepted);
        }
        let receipt = ReceiptEnvelope::decode_2718_exact(&receipt_rlp)
            .map_err(|_| ReceiptError::InvalidReceipt)?;
        if receipt.as_receipt().and_then(|r| r.status.as_eip658()) != Some(true) {
            return Err(ReceiptError::InvalidReceipt);
        }

        let mut logs = receipt.logs().iter().filter(|log| {
            log.address.as_slice() == &state.emitter.0[..]
                && log.topics().first() == Some(&MessageRequested::SIGNATURE_HASH)
        });
        let log = logs.next().ok_or(ReceiptError::InvalidPing)?;
        if logs.next().is_some() {
            return Err(ReceiptError::InvalidPing);
        }
        let event = MessageRequested::decode_log_data_validate(&log.data)
            .map_err(|_| ReceiptError::InvalidPing)?;
        let ping_id = H256::from(event.applicationId.0);
        let len = event.payload.len();
        if event.sender.as_slice() != &state.sender.0[..]
            || ActorId::from(event.destination.0) != Syscall::program_id()
            || ping_id.is_zero()
            || len > 1024
        {
            return Err(ReceiptError::InvalidPing);
        }

        // One dynamic bytes argument: require its canonical ABI offset, length and padding.
        let data = log.data.data.as_ref();
        if log.topics().len() != 4
            || log.topics()[2][..12].iter().any(|&b| b != 0)
            || data.len() != 64 + len.div_ceil(32) * 32
            || data[..31].iter().any(|&b| b != 0)
            || data[31] != 32
            || data[64 + len..].iter().any(|&b| b != 0)
        {
            return Err(ReceiptError::InvalidPing);
        }
        if state.pings.contains_key(&ping_id) {
            return Err(ReceiptError::AlreadyAccepted);
        }
        state.pings.insert(ping_id, event.payload.to_vec());
        state.positions.insert(position);
        Ok(ping_id)
    }

    #[export]
    pub fn received(&self, ping_id: H256) -> Option<Vec<u8>> {
        self.0.borrow().pings.get(&ping_id).cloned()
    }
}

pub struct Receiver(RefCell<State>);

#[program]
impl Receiver {
    pub fn new(proxy: ActorId, emitter: H160, sender: H160) -> Self {
        assert!(!proxy.is_zero() && !emitter.is_zero() && !sender.is_zero());
        Self(RefCell::new(State {
            proxy,
            emitter,
            sender,
            positions: BTreeSet::new(),
            pings: BTreeMap::new(),
        }))
    }

    pub fn ping(&self) -> Ping<'_> {
        Ping(&self.0)
    }
}
```

## Verification

Check that the original submission finalized on Vara, that the consumer reply was `Ok(ping_id)`, and that `Ping.Received(ping_id)` returns the expected payload. A finalized checkpoint makes proof verification possible; it is not delivery. Test that direct calls, wrong emitters or event signatures, malformed payloads, and duplicate pings do not change receiver state.
